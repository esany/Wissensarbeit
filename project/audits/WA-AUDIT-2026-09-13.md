## Executive assessment

`Wissensarbeit` is no longer only a declarative Foundation. It is now an operational reference implementation / research prototype for Git-native AI-supported knowledge work with several real continuity and control mechanisms exercised end to end.

Its motivating problem remains coherent:

> Enable a domain/problem owner to concentrate on problem meaning, purpose, priority and material acceptance while the system carries as much research, competence activation, technical translation, structuring, implementation, traceability, assurance and project operation as can be automated without confusing AI capability with human/domain authority.

The current system is strongest at continuity, provenance, authority separation, deterministic assurance and fail-closed control. The main remaining challenge has shifted from “can project state survive chat/context loss?” to “can multiple persistent state surfaces remain semantically current together, and can the support system measurably enable domain work without becoming the work itself?”

## Cross-pilot findings from paleo-type

Detailed Generic-Fit evidence is owned by:

`pilots/paleo-type-2026-09-13/generic-learnings.md`

The most consequential generic observations are summarized here only so the whole-repository audit is restartable.

### A. Canonical ownership and derived views are different capabilities

A generated, reproducible view can still lag a lifecycle transition if the canonical input it is bound to has not itself advanced. Freshness must therefore be reasoned about across state transitions, not only file reproducibility.

### B. Evidence readiness is a ladder, not a boolean

The pilot repeatedly distinguishes identity, retrievability, staging, target-context inspectability and research readiness. “Evidence exists” must not inherit “the current task can inspect it”.

### C. Analysis/work units may be hypotheses

Directly observed structure, cross-source correspondence range, analysis unit and functional interpretation are distinct. A support system must not silently turn a convenient grouping into domain truth.

### D. Review independence is evidence-basis dependent

A fresh reviewer/agent is not substantively independent if its premise comes from the same derived representation. Independence of context is weaker than independence of evidence basis.

### E. Support dominance is a real generic failure mode

A project can accumulate locally valid activation, state, CI, access and coordination work before the first new domain/scholarly action. Support work can recursively justify more support work without knowledge gain.

Candidate control principle:

> Before support work expands, identify the first bounded domain action that can create new knowledge or establish an evidence ceiling. Additional support work before that action needs to materially enable it or protect a necessary invariant.

This sharpens existing `R-007`, `Q-LEAN`, `REQ-008`, `BB-OPERATE` and `BB-LEARN`; it does not require a new Building Block.

### F. Real blocker / evidence ceiling is a valid terminal result

A workblock may correctly end in a real blocker or evidence ceiling. This must not be converted into artificial completion or extra support scope merely to produce visible activity.

### G. Semantic boundaries matter more than universal vocabulary

Terms crossing domain, software, AI, project and human surfaces must preserve claim type, evidence/authority, scope and uncertainty. Reusing the same word does not create semantic equivalence.

## Generic capability synthesis

The combined repository and pilot evidence supports a small generic process kernel rather than a universal workflow architecture:

```text
resolve
→ establish authority
→ materialize/qualify evidence
→ compile bounded context
→ perform domain work / judgement
→ validate deterministic invariants
→ control state transition
→ derive human/machine views
→ harvest learning
```

The domain-work/judgement step is intentionally not generalized into a deterministic algorithm.

Useful generic technical primitives remain:

- resolver;
- validator;
- context compiler;
- evidence/readiness inspector or adapter;
- transition guard;
- derived-view compiler;
- learning harvester;
- bounded execution preflight.

The audit does **not** support early introduction of:

- a universal ontology;
- large knowledge graph;
- workflow engine/state-machine platform;
- sprawling agent-role system;
- master prompt as project state;
- autonomous canonical writer;
- generic information-gain scoring framework.
