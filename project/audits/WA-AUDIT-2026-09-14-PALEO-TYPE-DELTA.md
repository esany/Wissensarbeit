The strongest generic lesson is **not** that Wissensarbeit needs a generic research-framing workflow, Candidate-Question schema, scoring model, permanent competency topology or control-plane architecture.

## 1. Execution maturity is ahead of task/question formation maturity

`paleo-type` has become strong at executing, evidencing, reviewing, persisting and restarting an already-selected bounded task. Its 2026-09-14 Research programme explicitly investigated the weaker pre-task side: forming, comparing and challenging scientifically consequential candidate questions.

The final PR #192 experiment positively demonstrated that several serious questions can be generated from each of three heterogeneous source states, while substantive question formation remains strongly source- and purpose-sensitive.

Recurring operations were thin and adaptive rather than one universal framing procedure:

- consequence-sensitive relation finding;
- question-dependent analytical scale/context adjustment;
- discriminating-evidence identification;
- source-critical reformulation;
- explicit evidence ceilings;
- preserving alternative directions until the proper priority authority acts.

The evidence still does **not** justify one linear framing layer, Candidate-Question schema, scientific scoring model, fixed competency topology, fixed AI allocation, Human-Owner UI or generic workflow/control-plane architecture.

### Wissensarbeit implication

Do not generalize the exploratory `paleo-type` research architecture into Core machinery.

The existing generic capabilities already own the relevant concerns:

- `BB-CONTEXT` — bounded task context;
- `BB-COMPETENCE` — needed competencies and gaps;
- `BB-RESEARCH` — evidence/SOTA/fit;
- `BB-INTEGRATE` — Generic-Fit and consequence reconciliation;
- `BB-ASSURE` — evidence-depth and judgement boundaries;

- `BB-LEARN` — failure → candidate learning without novelty-driven promotion.

The current problem is operational fidelity and activation of existing capabilities, not evidence for a fifteenth Building Block.

## 2. Context fidelity is claim-dependent, not equivalent to maximal context

The earlier P2 idea correctly identified silent material omission as a failure. The enlarged `paleo-type` evidence adds the opposite failure mode: supplying all available context at all stages can also be wrong.

Examples:

- contamination-sensitive direct source reading may require comparator/semantic context to be deliberately withheld initially;
- dating a correspondence item may require relational/provenance evidence as constitutive evidence from the start;
- historical-account questions may require aggregation beyond one stable entry address;
- a wider comparison range may be relevant evidence without becoming the source-side analysis unit.

Therefore P2 should not operationalize this naive rule:

> all material context must always be present in the immediate execution context.

A more defensible fidelity invariant is:

> For the current bounded work/question and input snapshot, every known material input must remain dispositioned and reconstructable as included, deliberately omitted, unresolved/deferred or otherwise explicitly bounded, with rationale and authority/uncertainty preserved. Immediate inclusion is claim-dependent.

This allows a material item to be intentionally omitted from the immediate model context while still remaining visible in the fidelity record and available under a stated refresh/reactivation condition.

## 3. Fresh context is weaker than independent evidence-basis review

The independent Wissensarbeit restart PASS proves an important continuity property: a fresh execution context can reconstruct persistent project state without prior chat history.

`paleo-type` demonstrates a separate problem: a fresh reviewer can inherit the same unsupported derived premise and therefore fail to provide substantive epistemic independence.

For future assurance language, keep these distinct:

```text
fresh-context restart assurance
!=
independent evidence-basis review
```

No new assurance subsystem is justified yet. The distinction is a candidate refinement for `BB-ASSURE`/`BB-TRACE` and a useful P2 test dimension when context sources include derived representations.

## 4. Resource/readiness state must not manufacture task authority

PR #175 corrected a concrete authority-laundering chain in `paleo-type`:

```text
resource unavailable
→ REAL BLOCKER
→ task not executable
→ canonical STOP / roadmap consequence
```

The corrected invariant is narrower: resource/readiness state describes whether the action that actually needs the resource is executable. It does not itself select priority, task-wide blocker status, substitute work or a roadmap transition.

### Wissensarbeit implication

P2 may preserve evidence/readiness state, but the fidelity/context layer must not derive stronger work authority from that state. This is a concrete negative regression candidate for the later implementation slice.

## 5. Analysis/work unit remains a hypothesis where evidence does not settle it

The #165/#166 history shows that these are different objects:

- stable source address;
- observed layout/text block;
- comparison/correspondence range;
- research locus;
- analysis unit;
- functional rule or historical interpretation.

A context compiler must preserve such distinctions when they are material; it must not collapse them because one representation is convenient.

The cross-source Research strengthens rather than weakens this point: Darwin correspondence and historical accounts require different useful analytical relations/scales from Reg. Ii 5.

### Wissensarbeit implication

Do not add a universal `analysis_unit` ontology to P2. Preserve source/claim semantics and explicit unresolved alternatives by reference to their owners instead.

## 6. Support progress and domain/knowledge progress remain distinct

The prior support-dominance finding remains valid. `paleo-type` has since also shown the complementary side: strong support controls can efficiently preserve a scientifically weak or inherited scope.

Therefore two review axes must remain distinct:

```text
Is the selected work/question scientifically/domain-appropriate?

Is the execution/support path economical, admissible and well controlled?
```

Wissensarbeit should not treat improved execution control as evidence that scope formation is solved. Conversely, the current evidence does not justify building a generic scientific-priority engine.

## 7. Rapid repository evolution makes snapshot identity part of fidelity

The movement from `paleo-type@833da352…` to `3df61570…` occurred while the original PR #33 evidence remained correctly pinned to its old checkpoint.

This demonstrates a practical multi-clock/freshness requirement:

> a context or audit can be internally correct and reproducible while no longer describing the current consumer state.

This reinforces the existing Wissensarbeit multi-clock finding rather than creating a new category.

P2 should therefore test whether a compiled context/fidelity record can identify the exact input snapshot and expose the condition under which it becomes stale or requires refresh.

## 8. Generic learning needs an evidence-to-promotion pipeline, not immediate architecture growth

The `paleo-type` 2026-09-14 sequence itself is useful Generic-Fit evidence:

```text

→ primary fixture analysis
→ preserve alternative explanations and uncertainty
→ heterogeneous cross-source comparison
→ Research integration
→ challenge pre-existing Concept Candidate
```

This is not proposed as a mandatory universal workflow. The important generic principle is weaker:

> evidence for a recurring need is not evidence for a particular solution form, and descriptive recurrence does not itself authorize normative/Core promotion.

That fits the existing `BB-LEARN`, `BB-INTEGRATE`, `R-002`, `R-003`, `R-006` and `R-007` semantics.

### Candidate deterministic invariants for P2 preflight

The preflight should test whether the existing state can support regressions such as:

1. every producer-known material item is explicitly dispositioned;
2. silent material omission fails closed;
3. deliberate material omission with explicit claim-specific rationale can be valid;
4. omitted context is not treated as nonexistent;
5. unresolved/alternative state is not silently resolved during compression;
6. uncertainty is not strengthened or lost;
7. output authority is not stronger than its source/owner basis;
8. resource/readiness state does not create task/roadmap authority;
9. a derived representation does not count as independent evidence merely because the execution context is fresh;
10. a context bound to an older input snapshot does not present itself as current after a material state transition.

The exact fields and implementation remain intentionally undecided until preflight. Do not create a new knowledge store merely to satisfy this list.
